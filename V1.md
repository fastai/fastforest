# FastForest V1

FastForest V1 was a small regression forest built around one idea: make an approximate split search genuinely cheap, and retain its randomness as useful ensemble diversity rather than compensating for it with more optimization.

This document describes the intended algorithm and the design principles embodied in the original C++ implementation.

## Forest construction

The implementation built five independent regression trees. Each tree sampled 80% of the training rows uniformly with replacement, and trees were trained in parallel.

The input matrix was row-major `float`. A tree stored an array of pointers to its sampled feature rows and a matching contiguous target array, so sampling did not copy the feature values. These arrays were shuffled once before growing the tree.

## Naturally organized node rows

A node did not own a new collection of rows. It was represented by just a `start` position and row count within the tree's arrays.

After choosing a split, the node's entire row range was partitioned in place by swapping feature-row pointers and their matching targets. The left and right children therefore became two adjacent contiguous ranges of the same arrays.

This organization provided:

- constant-time creation of child row sets;
- no per-node row allocation or copying;
- good locality when scanning targets and row pointers;
- constant-time uniform sampling of a row from any node;
- a simple iterative depth-first builder using a stack of nodes.

## No-sort split search

V1 never sorted feature values. At a node containing `N` rows and `P` columns, it used:

```text
S = min(N, 160)
C = max(4, floor(S * sqrt(P) / 10))
```

It then:

1. Created `C` cutoff candidates.
2. For each candidate, selected a column uniformly and a row uniformly from the full node.
3. Used that row's value in the selected column as the cutoff.
4. Selected a random contiguous window of `S` node rows for split evaluation.
5. Passed every evaluation row across the small candidate array.
6. For each candidate whose cutoff placed the row on the left, accumulated the target count, sum, and squared sum.

The inner operation was just a feature lookup, comparison, and a few additions. With 40 columns at a large node, V1 evaluated about 101 candidates against 160 rows.

## Split criterion

Regression impurity was standard deviation. A candidate was scored using the row-weighted negative standard deviation of its left and right sampled children, and was accepted only when it strictly improved on the unsplit node.

Candidate children had to contain at least both:

- 5% of the evaluation rows; and
- one third of the configured minimum node size.

The default minimum node size was 25. Nodes smaller than this, or with effectively identical sampled targets, became leaves. Node predictions were target means.

The evaluation sample was approximate, but an accepted split was always applied to every row in the node. Thus split discovery had bounded cost while the resulting tree partition remained exact.

## Prediction

Prediction followed one conditional at each decision node until reaching a leaf. Forest prediction was the mean of the five tree predictions.

## Key design ideas

### Approximation must remove work

The split search avoided sorting, exhaustive cutoffs, and full-node split statistics. Apart from partitioning an accepted split, work at a large node was bounded by the 160-row evaluation window and the small candidate array.

### Randomness is a feature

Bootstrap sampling, the initial shuffle, evaluation-window selection, feature selection, and cutoff selection all varied between trees. The computation omitted for speed became additional forest diversity and regularization.

### Preserve natural organization

Rows stayed in one tree-local structure and were progressively partitioned into contiguous node ranges. The algorithm worked with this organization directly instead of repeatedly constructing, sorting, or balancing auxiliary structures.

### Keep the hot loop simple

The central split-evaluation loop operated on a compact candidate array and accumulated only three statistics per candidate. Its structure was predictable and suitable for compiled, vectorized execution.

### Parallelize where independence is free

Trees were independent, so training parallelized over trees without coordination inside tree growth.

### Separate approximate search from exact structure

Only the choice of split used sampled statistics. Once selected, the cutoff partitioned the complete node. This allowed training cost to depend only weakly on dataset row count while retaining ordinary decision-tree prediction.
